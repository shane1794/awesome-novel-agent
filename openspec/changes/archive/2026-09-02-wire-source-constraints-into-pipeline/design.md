## Context

- The dependent change `add-zhuque-source-defense`: the knowledge file (`knowledge/anti-ai/structural-heat.md`) and `tools/check-chapter.py` already exist.
- The existing pipeline: novel-agent dispatch, then prompt-crafter (writes prompts), writer (drafts), anti-ai (Phases 1-4 + Gate G), reader, archive. Skills are each agent's SOP instructions, with frontmatter reference paths verified against the deployment layout by `check-agents.py`.
- The project skeleton is generated by `templates/` + `tools/init.py`, and E2E assertions in `tools/test_platforms.py` cover seven-platform output.

## Goals / Non-Goals

**Goals:**

- Minimize changes at the three wiring points (writer/prompt/anti-ai): only add references and steps, without rewriting the existing SOP structure.
- Evolution-mechanism files work out of the box: new projects ship with the skeletons on init, and old projects can gain them via sync.
- Author-visible wording is compliant.

**Non-Goals:**

- Do not change the dispatch contract (the novel-dispatch.md phase table stays put; detect-loop's optional phase belongs to `add-detect-loop-skill`).
- Do not do automatic submission (everything in this change is offline).
- Do not write a migration script for old projects (existing projects can add the `sandbox/` files manually per the README; sync only backfills the skeletons).

## Decisions

1. **The anti-closed-loop card goes in writing-execution (the writer's SOP), not prompt-crafting.**
   The card is a self-check action during writing and belongs to the execution stage; prompt-crafting only writes the bans into the prompt. Each place does its own job, avoiding two sources maintaining the same content.
2. **Structural bans are injected into prompts as "references plus entries", not as a full copy of the knowledge file.**
   The knowledge file keeps being revised, and a full copy would create two drifting copies; prompts list short ban entries, with decision details pointing at the knowledge file.
3. **The anti-ai structural scan is a pre-step of Phase 1, not a new Gate.**
   Gate A-F numbering stays stable (many other docs reference it), and structural hits get their own section in the report. The alternative, "add a Gate H", was rejected: Gates are word-and-sentence-level categories, while structural hits are whole-paragraph or whole-scene level, and mixing them would break the report format.
4. **check-chapter failure semantics merge into the existing degradation system.**
   anti-ai Phase 2 already has "missing / no Python, degrade" semantics for check-prose; check-chapter follows the same set, adding no new blocking conditions.
5. **Skeleton files go in `templates/sandbox/`.**
   `sandbox/` is an existing project directory (trial writing / sandbox); evolution-mechanism files are also project workspace files and do not pollute `settings/` (settings) or `archives/` (archived text).
6. **Dual-track naming in skill text.**
   Skill internals use internal terms such as "structural heat source" and "regression library", while author-visible examples and notes use everyday language ("paragraph structures that look AI-written at a glance"); the reference table is updated with the new terms in sync.
7. **Three anti-conflict disciplines for prompt injection (protecting generation quality).**
   Large models are sensitive to contradictory and repeated instructions: two wordings running in parallel make the writer waver during execution, and repeated entries amplify the effect of wrong thresholds. So: (1) **single authoritative source**: the knowledge file is the only source of details, and prompts hold only short entries plus references, never a full copy; (2) **new scales are not redefined**: only inject scales not covered by existing rules (question-answer round beats), while existing wordings (Gate E5 sentence counts, common-rules dash usage rulings, Gate F chapter endings) are referenced, never restated; (3) **explicit adjudication order**: author settings and chapter outline > genre knowledge > structural defaults > detection optimization is written into the ban section, so the writer never has to guess priorities in a conflict. The source pack's "minimal chapter endings / hook staging with interruption" directly conflicts with webnovel hook culture, so it is demoted to an on-demand advanced item that is off by default.

## Risks / Trade-offs

- The three skills are shared by all genres, so hard-coding numbers into structural bans (such as "no more than 8 beats per 300 words") may not fit some genres. Mitigation: bans are written as "default plus adjust by style", with defaults from measured data.
- Longer prompts cost more tokens. Mitigation: the ban section stays within about a dozen lines, with details kept outside in the knowledge file.
- New skeleton files in init make `sync-project --check` on existing projects report "updates available". Mitigation: this is expected behavior, flagged in the release notes.
