## Purpose

Wire structural-heat-source knowledge into the key nodes of the writing pipeline, so AI heat sources are avoided before generation and identified first during scanning, and give each book file carriers for "detection battle to rule distillation". The goal is to push the number of external-detection fix rounds to a minimum from the source.

## ADDED Requirements

### Requirement: Writer pre-writing anti-closed-loop card

Before drafting each scene, the writing-execution flow MUST produce a five-line anti-closed-loop card: what the character needs to accomplish right now / whose immediate reaction the resistance comes from / how far into the performance this scene goes before stopping / which outcomes are not explained / which piece of information is left for the next scene. When items 3-5 cannot be answered, the writer MUST NOT start writing that scene's main text.

#### Scenario: Constraints come first
- **WHEN** the writer drafts any scene per the flow
- **THEN** the constraint notes contain that scene's five-line anti-closed-loop card, with items 3-5 each having a clear answer

#### Scenario: Wording compliance
- **WHEN** checking the new text in writing-execution.md
- **THEN** author-visible wording uses everyday language and contains no internal terms (checked against author-communication.md)

### Requirement: Pre-writing prompt injection of structural bans (single authoritative source, zero semantic conflicts)

Prompts generated by prompt-crafting MUST include a structural-ban section and MUST satisfy the anti-conflict constraints:

- Entries are limited to new scales not covered by existing rules: a cap on question-answer round beats (running in parallel with Gate E5's "consecutive pure-dialogue sentence count" scale without replacing it, and not restating the action-insertion frequency), cold chapter openings, a ban on stacking multiple payoff receipts in the same scene (with an explicit exemption for a single-receipt payoff delivery in one scene), and bridge-chain/proof-chain bans;
- Chapter-end entries keep only "no summary/elevation/preview" (same direction as Gate F, referenced not restated), and MUST explicitly state "chapter-outline landing points take priority"; "hook staging with interruption" is an on-demand advanced item and is not written into prompts by default;
- The ban section MUST carry an adjudication-order statement: author settings and chapter outline > genre knowledge > structural defaults > detection optimization;
- Decision details MUST reference `.claude/knowledge/anti-ai/structural-heat.md` rather than copying the knowledge file in full;
- The ban section MUST NOT create numeric or semantic contradictions with existing prompt rules (existing wordings for punctuation, dialogue frequency, and the like are all referenced, never redefined).

#### Scenario: Prompt contains the bans
- **WHEN** prompt-crafter generates a writing prompt for any chapter
- **THEN** the prompt contains the structural-ban section, with the knowledge-file reference path and the adjudication-order statement, and `check-agents.py` verifies that path is valid

#### Scenario: No contradictory injection
- **WHEN** checking the ban section against the existing rule list (Gates A-F, common-rules numeric wordings, existing prompt pacing rules)
- **THEN** there are no dual numeric wordings for the same phenomenon and no instructions pointing in opposite directions (such as a punctuation hard ban versus usage-based judgment)

### Requirement: anti-ai scans structure before cleaning sentences

anti-ai Phase 1 MUST run a structural-heat-source scan before the Gate A-F word-and-sentence scan (against the structural-heat.md high-risk structure list); structural hits MUST enter the fix scope first (fix structure first, then clean sentences). When the same problem hits both a structural and a word-and-sentence rule, it MUST be counted only once, categorized under whichever category takes effect first, to avoid double counting. Phase 2 machine pre-screening MUST call `check-chapter.py` alongside `check-prose.py` (`check-chapter` hard hits merge into the Gate A/B list; `check-prose` behavior is unchanged).

#### Scenario: Structure-first grading
- **WHEN** a manuscript has both a structural-heat hit and a Gate A word-and-sentence hit
- **THEN** the fix order is structure first, then word and sentence, and the report lists structural hits separately

#### Scenario: Dual-script pre-screen
- **WHEN** anti-ai Phase 2 runs the machine pre-screen
- **THEN** both scripts are called; `check-chapter` hard hits are handled as hard failures, and when the script is missing or cannot run, it is marked per the existing degradation semantics (non-blocking)

### Requirement: Project skeleton includes evolution-mechanism files

Projects generated by init MUST include `sandbox/detect-battles.md` (battle-log template), `sandbox/prose-regressions.txt` (regression pattern library, empty library plus usage notes), and `sandbox/locked-lines.txt` (locked-lines whitelist example); all three MUST be covered by sync's update detection and by `test_platforms.py` E2E tests.

#### Scenario: Initialization output
- **WHEN** running `python tools/init.py <project path> --platform <any platform>`
- **THEN** the three skeleton files exist in the project `sandbox/`, and the E2E test assertions pass

#### Scenario: Battle log usable
- **WHEN** opening `sandbox/detect-battles.md`
- **THEN** the template contains a round-by-round log table (round / change / per-segment results / conclusion) and a "distilled patterns" section, with usage notes in author-readable language
