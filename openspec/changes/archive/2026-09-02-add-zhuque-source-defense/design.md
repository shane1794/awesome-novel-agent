## Context

- `tools/check-prose.py` already exists: ported from human-writing (MIT), it handles AI-flavor hard bans and statistical shape, reports only and never edits text, and is called by anti-ai Phases 2 and 4.
- The source pack's `check_chapter.py` is hard-coded for a single book: its 29 family regexes mix book-specific regression strings (character names, plot sentences), ledger paths (`参考资料/连续性数字台账.md`, a continuity-numbers ledger), and book-title keyword tables. This project is a general tool library for many books and genres, so it cannot be ported directly.
- Knowledge side: the pack's `anti-ai-writing.md` is an old human-writing fork (36KB, carrying a "same-name copy x5" sync note), while the repo version is a refactored edition (13KB, with thresholds pushed down into common-rules.md). The two versions cannot overwrite each other at file level.

## Goals / Non-Goals

**Goals:**

- Structural-heat-source knowledge enters the repo, generalized (usable for any genre or book).
- The chapter-delivery check tool deploys to seven platforms, with book-specific assets kept outside as project files.
- Responsibilities are clearly separated from check-prose.py, with no overlap.

**Non-Goals:**

- Do not change check-prose.py's existing thresholds.
- Do not wire the skills pipeline in this change (wiring writing, prompt, and anti-ai belongs to `wire-source-constraints-into-pipeline`).
- Do not add any book-specific regression strings, character names, or ledgers to the repo.
- Do not add any Zhuque automation scripts or protocol docs (local tools that never enter git).

## Decisions

1. **A new tool, `check-chapter.py`, not merged into check-prose.py.**
   Reason: different responsibilities (AI-flavor statistical shape vs. delivery defects located line by line); merging would bloat a single script and make the exit-code semantics fight each other, while in the anti-ai flow the two scripts can run one after the other. The alternative, "merge them", was rejected: check-prose was ported from upstream, and keeping its structure aligned with upstream makes future syncs easier.
2. **Book-specific assets kept outside in the project `sandbox/`.**
   The regression pattern library `sandbox/prose-regressions.txt` and the whitelist `sandbox/locked-lines.txt` hold one entry per line in UTF-8; the tool only implements the reading logic, and missing files are skipped. Skeleton files are generated by `wire-source-constraints-into-pipeline` (at the templates layer); this change first guarantees "it runs even with no files".
3. **Check items take only general regexes, graded hard/warning, with punctuation conventions aligned to common-rules.**
   Hard means objective errors (label-style sandwiches, nested quotes, half-width quotes, word-count reconciliation mismatches, regression-string hits); warning means semantic adjudication is needed (dashes/ellipses judged by the common-rules usage, broad sandwiches, question-answer in one paragraph, adverb density, trailing labels). The source pack's "zero dashes / zero ellipses" is a single-book iron rule that conflicts with the repo's existing wording (usage-based retention allowed, prompting only at 3 or more in a paragraph), so it is not default behavior; books that need it use a book-level whitelist or switch. Checks in the source pack that depend on a book-specific word table (the circled-5 short-word double-quote check, ledger-constant scanning) are not taken; the trailing-label check depends on a character-name table, so it is generalized to a narrow "pronoun plus say/ask" set and set to warning grade.
4. **Platform-convention word counts only count, with no threshold.**
   The source pack's 3010-or-more is a single book's platform requirement; this project spans many platforms and books, so word-count minimums are book-level settings and the tool only outputs itemized counts.
5. **Standard library only, plus Windows encoding protection.**
   Consistent with repo Python conventions: snake_case, `reconfigure(encoding="utf-8")`, and a docstring stating usage and exit codes.
6. **The knowledge file is rewritten in generic terms rather than mounted verbatim.**
   Book names, character names, and chapter numbers are removed, while the structural shapes and measured scores are kept; reference paths follow repo conventions and use the post-deployment path (the `.claude/knowledge/anti-ai/...` base).

## Risks / Trade-offs

- Generalizing the rewrite loses some of the source pack's contextual detail. Mitigation: "keep the measured data, and keep the original pack outside the repo" (the original pack stays on the user's machine and is not added to the repo).
- Warning-grade checks (broad sandwiches and the like) false-positive more than hard items. Mitigation: output clearly marks them "needs adjudication" and does not block delivery; false-positive patterns are later caught by each book's regression library.
- The regex family matches the source pack under Python `re`, but cross-platform line endings (CRLF) differ. Mitigation: test cases cover CRLF input.
