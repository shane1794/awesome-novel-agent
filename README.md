## What You Need

- A computer with [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview), [OpenCode](https://github.com/sglaboratory/opencode), Reasonix, **Codex**, **ZCode**, **DeepSeek Harness (dsh)** or **[Grok Build](https://docs.x.ai/build/overview)** installed
- Python 3.9+ (the one bundled with macOS works; 3.11+ recommended)
- pyyaml for OpenCode / Codex / ZCode / dsh / Grok Build (`pip install pyyaml`; use `pip install --user pyyaml` if the system Python is permission-restricted)
- About 1 minute to install

## Installation

**No copy-pasting needed.** Open the AI tool you use (Claude Code / OpenCode / Codex / ZCode / DeepSeek Harness / Grok Build) and tell it:

> **Install awesome-novel-agent for me**

The agent will download from <https://github.com/modoojunko/awesome-novel-agent> (if it can't find it, paste this repo URL to it) and run the prepared installer `./install.sh <platform>` itself:

| Platform | Install location |
|----------|------------------|
| Claude Code | `~/.claude/skills/awesome-novel/` |
| OpenCode | `~/.config/opencode/skills/awesome-novel/` |
| Codex | `~/.codex/skills/awesome-novel/` |
| ZCode | `~/.zcode/skills/awesome-novel/` |
| DeepSeek Harness | `~/.dsh/skills/awesome-novel/` |
| Grok Build | `~/.grok/skills/awesome-novel/` |

You're done once you see **"安装完成"** (Installation complete). To install manually, clone the repo and run `./install.sh <platform>` (`claude-code` / `opencode` / `codex` / `zcode` / `dsh` / `grok`); on Windows (PowerShell) run `install.ps1 <platform>`. `install.sh` / `install.ps1` also support `deepseek-tui` / `hermes` / `openclaw` (non-primary platforms). The installer checks the Python version (3.9+ required) and the pyyaml dependency (opencode / codex / zcode / dsh / grok only), and aborts with clear messages instead of failing later when `init.py` / `sync-project.py` run.

**Reasonix:**

Reasonix skills are deployed **per-project** (into `.reasonix/skills/`), not globally, no `install.sh`. Tell Reasonix **"Install awesome-novel-agent for me"** and it will clone the repo and run `init.py` to initialize your novel project directly:

```bash
git clone https://github.com/modoojunko/awesome-novel-agent.git && cd awesome-novel-agent
python tools/init.py <novel-project-path> --platform reasonix
cd <novel-project-path> && reasonix code
```

> Use `--genre <number>` to pick a preset genre; without it, init.py asks interactively.

**ZCode:**

ZCode's skill convention (directory + `SKILL.md`) is compatible with Claude Code's, but it has **no project-level agents directory**, the 9 agents are deployed as skills (agents == skills). The skill itself is installed globally via `install.sh`; project contents are deployed per-project to `.zcode/` by `init.py --platform zcode`:

```bash
./install.sh zcode
python ~/.zcode/skills/awesome-novel/tools/init.py <novel-project-path> --platform zcode
```

**DeepSeek Harness (dsh):**

dsh's skill convention (directory + `SKILL.md`) is compatible with Claude Code's, but it has **no project-level agents directory** (subagents are a runtime capability), the 9 agents are deployed as skills (agents == skills), and `<projectRoot>/.dsh/skills/` is dsh's project-level skill root (auto-discovered, highest priority). The skill itself is installed globally via `install.sh`; project contents are deployed per-project to `.dsh/` by `init.py --platform dsh`:

```bash
./install.sh dsh
python ~/.dsh/skills/awesome-novel/tools/init.py <novel-project-path> --platform dsh
```

**Grok Build:**

Grok Build's skill convention (directory + `SKILL.md`) shares its roots with Claude Code's and is **natively compatible**; custom agents are deployed to the project `.grok/agents/*.md` (Grok's native discovery path). The skill itself is installed globally via `install.sh`; project contents are deployed per-project to `.grok/` by `init.py --platform grok`:

```bash
./install.sh grok
python ~/.grok/skills/awesome-novel/tools/init.py <novel-project-path> --platform grok
```

See the [ZCode Integration](#zcode-integration) section below for details.

> **DeepSeek Harness users, note:** the skill is installed to `~/.dsh/skills/awesome-novel/`; after init, the 9 agents are deployed as SKILL.md under the project `.dsh/skills/` (dsh has no project-level agents directory, agents are skills), and dsh discovers them automatically. See the [dsh Integration](#dsh-integration) section below for details.

## Start Writing

After the skill is installed, launch Claude Code / OpenCode / Codex / ZCode / DeepSeek Harness / Grok Build in the directory where you want your novel project and type:

> **/awesome-novel**

(In Codex, type `/use awesome-novel`, or just say "help me write a novel".)

The skill detects the directory state: for a new directory it confirms with you, then runs `init.py` to scaffold the novel workspace locally (project skeleton, agent definitions, knowledge base, memory files) before entering the writing flow. When you enter the same project again, say `@novel-agent` or "help me continue writing" to resume from where you stopped.

Reasonix users: run `reasonix code` in the project directory, then type `@novel-agent` to enter the writing flow. ZCode users: just say "help me write a novel" or "help me continue writing" in the project directory (ZCode has no `@` syntax, agents are skills, and novel-agent is auto-discovered by ZCode). DeepSeek Harness users do the same, just say "help me write a novel" or "help me continue writing" (dsh routes skills by name/description automatically). Grok Build users: type `/awesome-novel` or say "help me write a novel".

The Agent will guide you through the following steps. The system is driven by 9 AI agents working together, automatically detecting progress and dispatching tasks; you only confirm the direction and review the content.

```
novel-agent (top-level entry, loaded via @novel-agent)
  ├─ setup → dispatches updater (write settings)
  ├─ outline → dispatches volume-planner (volume outline) → chapter-planner (chapter outline)
  ├─ draft → dispatches prompt-crafter (prompt) → writer (prose)
  ├─ anti-ai → dispatches anti-ai (remove AI flavor)
  ├─ review → dispatches reader (deep review, optional)
  └─ archive → dispatches updater (archive + lore-keeping)
```

> The diagram above is the user-facing main flow; the full dispatch table (including style re-distillation, post-archive rewrites, memory fallback, and more) lives in `skills/novel-dispatch.md`.

novel-agent only dispatches and verifies, it never writes content directly. Sub-agents handle their specialized tasks, and after finishing they mark their order as `status: DONE` to signal completion.

### One-Time Setup

On first novel, the Agent discusses these areas. **No need to decide everything at once**: skip what you don't know and fill in later:

1. **Genre**: Xianxia (immortal cultivation), urban, mystery, historical... just say what you have in mind. Agent auto-configures writing style and pacing templates based on genre. You can also pick directly from the 24 built-in genre profiles and skip manually tuning the style
2. **World Setting**: What world does the story take place in? Any special rules? (e.g., "cultivation world where spiritual roots determine talent")
3. **Main Characters**: Who's the protagonist? What kind of person are they? Agent discusses personality, abilities, and growth history for each character
4. **Writing Style**: Prefer more description or more dialogue? More classical or modern tone? Can also import a novel you like to extract its style

### Planning the Story Framework

After setup, Agent helps plan the overall story structure. Planning advances on four dimensions at once:

1. **Emotional Arc**: How does the reader's emotion change from the start of the volume to the end? A wish-fulfillment volume runs "oppression, oppression, rise, face-slapping comeback, showing off", a mystery volume runs "tension, closing in, shock, relief"
2. **Conflict Ladder**: Break the core conflict into 2-4 layers of rising obstacles, each harder than the last, with a key turning point between layers
3. **Information Gap**: Be explicit about "who knows what, and who does not". Each volume defines its start and end points, and each chapter plays out the gap's dynamic change (set it up, use it, reveal it, open a new one)
4. **Scene Cards**: Break each chapter into 2-5 scene cards, each with three elements: what the protagonist wants to do, what stands in their way, and what hook makes the reader want to keep reading

> **Don't know the ending?** Tell Agent "I only know the beginning" and it will still help plan the first volume.

### Chapter Writing Loop (Multi-Agent)

9 agents collaborate, novel-agent (the director) dispatches sub-agents based on progress. You review and decide:

| Step | Responsible Agent | What Happens |
|------|-----------------|--------------|
| **① Chapter Outline** | chapter-planner | (dispatched by novel-agent) Inherits the volume's emotional arc, conflict ladder, and information-gap position, designs the in-chapter micro-arc, small conflict ladder, and information-gap dynamics, and breaks it into scene cards. You review and say "OK" or "change this" |
| **② Prompt** | prompt-crafter | (dispatched by novel-agent) Assembles a 6-element clean prompt from the outline, anti-AI rules, and style preferences |
| **③ Write** | writer | (dispatched by novel-agent) Writes the full chapter from the prompt |
| **④ Remove AI Flavor** | anti-ai | (dispatched by novel-agent) Gate A-F pipeline detects and removes AI traces, with quantified scoring and grading |
| **⑤ Review** | reader (optional) | (dispatched by novel-agent) 10-dimension, 60+ item deep review, diagnosing item by item against the outline, settings, and previous text |
| **⑥ Archive** | updater | (dispatched by novel-agent) After you confirm, archives the finalized draft, auto-updates character status, appends the emotional arc, merges style preferences, and checks hook health and volume boundaries |

**Dispatch rule:** `@novel-agent` is the top-level entry point, loaded by the main AI to play the director role. novel-agent dispatches sub-agents via the Agent tool and never writes content directly. After finishing, a sub-agent overwrites its order as `status: DONE` (without deleting the file), and novel-agent detects it and advances to the next phase.

After chapter one, Agent asks "Continue to the next chapter?"

### Automation

- **Distill Style** (style-distiller): import reference samples or use archived chapters to automatically extract quantified style parameters (sentence length, dialogue ratio, adjective density, and more), write them into the style master card and scene cards, and inject them sparsely into prompts by scene; recalibrate incrementally after each archive, so it fits your style better the more you write
- **Remove AI Flavor** (prompt-crafter + writer + anti-ai): prompts are assembled with anti-AI rules injected, prose self-checks as it is generated, and the standalone anti-ai agent runs the Gate A-F pipeline detection with quantified scoring and grading
- **Dynamic Memory** (multiple agents + updater): agents record your writing preferences and feedback live in conversation (good and bad examples); at archive time updater cleans up, deduplicates, and compresses as a fallback. High-frequency rules are promoted to permanent memory (`.claude/knowledge/permanent-memory.md`), so it understands you better the more you write
- **Track Foreshadowing** (updater): at archive time, automatically scans for unfulfilled and newly planted hooks, and checks staleness and concentrated-payoff risk
- **Manage Character Status** (updater): after each chapter is archived, automatically appends character status history, emotional arcs, and relationship changes. When writing the next chapter, Agent knows the latest state
- **Pacing Check** (updater): alerts you when there are more than 3 consecutive high-tension chapters or more than 2 consecutive uneventful chapters
- **Volume Boundary Detection** (updater): when a whole volume is done, automatically outputs a report and asks which direction the next volume should take

## FAQ

**Q: I'm not a programmer, can I install it?**

Yes. Open your AI tool and tell it "Install awesome-novel-agent for me, the repo is at https://github.com/modoojunko/awesome-novel-agent". The agent runs the installer itself, with no copy-pasting of commands. The only requirement is having Claude Code, OpenCode, Reasonix, Codex, ZCode, DeepSeek Harness, or Grok Build installed.

**Q: I upgraded the skill, how do I migrate my existing novel projects to the new format?**

When you launch in the current project directory after an upgrade, Agent auto-detects the old format and guides you through migration. Core logic: old files moved entirely to `old/` directory for backup, new project skeleton initialized in place, then old format settings converted field by field to new format. Archived prose copied directly; work-in-progress not migrated. You can manually delete `old/` after confirming migration is correct.

**Q: Can I change settings mid-writing?**

Yes. Just tell Agent "Change XXX in the world setting" or "I want to adjust this character's personality" and it will update it for you.

**Q: Generated text has AI flavor, what do I do?**

The default config is "low AI flavor": common machine-phrase patterns are banned, and writing is auto-checked after it is done. The dynamic memory system records how you revise AI-written text and turns it into your own rules, which are then avoided automatically.

**Q: Can I use my own writing style?**

Yes. After project creation, there's a writing style file where you can write in your preferences, and all subsequent chapters will follow this style.

This skill also supports Reasonix (DeepSeek's terminal AI agent, which uses byte-level stable prefix caching to cut inference cost).

Unlike Claude Code / OpenCode, Reasonix deploys skills **project-level**, every novel project generates `.reasonix/skills/` (11 SKILL.md files, agents == skills) at init time; nothing is installed globally.

### Install the framework source

Tell Reasonix **"Install awesome-novel-agent for me"** and it clones the repository locally (project-level deployment, not global).

### Initialize a project

Run init.py in the project directory (or a target path), specifying the Reasonix platform:

```bash
python tools/init.py <novel-project-path> --genre <number> --platform reasonix
```

### Start writing

After initialization, enter the project directory and start Reasonix:

```bash
cd <novel-project-path> && reasonix code
```

Then type `@novel-agent` to enter the writing loop. In Reasonix, novel-agent dispatches sub-agents with `run_skill`; the order-file protocol is identical to the other platforms.

### Project structure differences

A Reasonix project deploys agent definitions as skills under `.reasonix/skills/` and produces no `.claude/`:

```
.reasonix/
├── skills/               # 11 SKILL.md files (agents == skills)
│   ├── novel-agent/SKILL.md
│   ├── writer/SKILL.md
│   ├── volume-planner/SKILL.md
│   └── ...
├── knowledge/            # anti-AI rules, style preferences, permanent memory, format specs
└── memory/               # writing dynamic memory
```

Upgrade later with `python tools/sync-project.py <novel-project-path> --platform reasonix`.

### Writing Style Contributions (Writers)

If you are a writer with writing experience, you are welcome to contribute good-vs-bad examples by genre to the anti-AI writing library:

**What to contribute:** `knowledge/anti-ai/{genre}.md`: high-frequency AI-flavored sentence pairs for your genre

**Format:**
```markdown
# {Genre} Anti-AI Rules

> Genres this applies to: {genre-id}

## High-Frequency AI-Flavored Sentences: Good vs. Bad

### 1. {Problem type}

❌ "AI-flavored writing"
✅ "Human-feeling writing"

## Writing Notes

1. **{Note}**: explanation
```

**Principles for good-vs-bad examples:**
- ❌ Be specific: give real AI-flavored sentences, not abstract descriptions
- ✅ Be actionable: give human-feeling writing that can be copied, not "be natural"
- Each problem type contains one paired example: same scenario, same emotion, with a clear transformation

**How to submit:**
1. Fork the project
2. Create or edit a genre file under `knowledge/anti-ai/`
3. Submit a PR titled: `Anti-AI: add {Genre} good-vs-bad examples`

See [knowledge/anti-ai/README.md](./knowledge/anti-ai/README.md).
